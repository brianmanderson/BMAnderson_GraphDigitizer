How the Graph Digitizer works

A reader's guide to a browser-only tool that turns a picture of a chart into a table of numbers: what the user does, which part of the code does what, how the two automatic helpers (axis detection and line tracing) reach their suggestions, the calibration mathematics, and how every change is verified.

Repository BMAnderson_GraphDigitizer (Vite + React + TypeScript, strict). Live at brianmanderson.github.io/BMAnderson_GraphDigitizer/. docs/SPEC.md is the source of truth; where this overview and the spec differ, the spec wins.

0. Reading this page

Every box names one piece of the system. Its first line is the name (a function, module or user action), the second line in monospace is the file it lives in, and the text under it says in plain language what it does. Boxes are colour-coded by the layer of the code they belong to:

src/core — calibration engine (pure TypeScript, no DOM) src/auto — automatic analysis (pure TypeScript, no DOM) workers + OCR — Web Worker and Tesseract.js pool state + UI — reducer, history, canvas helpers, React components verification — tests, benchmarks, CI user action A Auto-detect axes pipeline B Auto-trace pipeline

Two facts shape everything below. First, the app is entirely client-side: the chart image is decoded in the browser, analysed in the browser, and never sent anywhere, because research figures may be unpublished. Second, nothing automatic is ever applied silently: both helpers only propose, draw their proposal as ghost markers, and wait for the user to press Accept.

1. The user's workflow in five steps

The side panel walks through three tabs (Image → Axes → Data) and the table sits under them; the toolbar holds file, zoom, undo and precision tools. In terms of what the user does:

1 · Load image
Image step · src/ui/loadImage.ts · src/ui/crop.ts
Drop a file onto the workspace, paste from the clipboard, or use Open image…. Any raster format the browser decodes is accepted (PNG, JPG, GIF, WebP, BMP; SVG is refused). A multi-panel figure can be cropped to the panel of interest at any time; refs and points already placed move with the crop.
→
2 · Choose axis scales
Axes step · src/core/scales.ts
X and Y are chosen independently: linear, log10, ln, reciprocal or date/time. The scale decides how a value is mapped to a straight-line coordinate before the geometry is fitted (section 5).
→
3 · Calibrate
Axes step · src/components/AxesStep.tsx · src/core/calibrate.ts
Click two points of known value on each axis (X1, X2, then Y1, Y2) and type their values; X1 and Y1 usually share the origin. Or press Auto-detect axes, review the suggested scales and values with their confidence badges, and press Accept suggestion. The fitted axes and gridlines are drawn over the image as a sanity check.
→
4 · Digitize
Data step · src/components/DataStep.tsx · src/components/Workspace.tsx
The Data step opens with Auto-trace line on: one click on a plotted curve or marker proposes its points, to accept or discard. After Discard (or Esc) each click places a point by hand. Several named, colour-coded lines can be digitized; the Move points tool selects and drags; a loupe magnifies the cursor, Snap centres a new point on the nearest marker, and arrow keys nudge the selection by sub-pixel steps. Everything is undoable.
→
5 · Output
src/ui/table.ts · src/ui/export.ts · src/ui/autosave.ts
A live table shows (x, y) per line and updates instantly when a scale or ref changes, because only pixels are stored. Export as CSV, copy as TSV (pastes into a spreadsheet), or download the whole project as JSON (image included) to reopen later. The work is autosaved to the browser's IndexedDB and restored on reload.

Values are never stored: points and refs are kept as image pixel coordinates, and every number in the table is recomputed through the calibration on demand. That is why recalibrating never moves a point.

2. Architecture

The code is split by what may run where. Two modules, src/core and src/auto, are pure TypeScript with no DOM access: they are type-checked without the browser's DOM library, so they can run unchanged in a Web Worker, in Node for the unit tests and benchmarks, and on the main thread. Everything that touches the canvas, React or storage sits above them.

Layers and files

Calibration enginesrc/core/DOM-freeruns in worker + Node
Scales
src/core/scales.ts
The five scale types, their domain rules (log needs v > 0, reciprocal v ≠ 0) and the forward/inverse transform that turns a value into a straight-line coordinate and back. Returns null instead of NaN when a value cannot be represented.
Dates (UTC)
src/core/dates.ts
Parses date/time text to epoch milliseconds and formats it back, always in UTC unless the text carries a zone, so the host computer's time zone and daylight-saving changes can never shift a value. Ambiguous forms such as 03/04/2024 are rejected rather than guessed.
Affine fit with typed errors
src/core/calibrate.ts
calibrate(refs, xScale, yScale) solves the pixel → value mapping from the four reference points and returns either a Calibration (with pixelToValue and valueToPixel) or a typed error with a user-facing message. Section 5 has the mathematics.
Project model and file migration
src/core/project.ts · src/core/projectFile.ts
The saved-project schema (image, calibration, datasets of pixel points, settings) with a version number. parseProject reads untrusted JSON (files and autosaves): it upgrades older versions step by step, validates every field, names the first damaged one, and refuses files from a newer version.
Automatic analysissrc/auto/DOM-freeruns in worker + Nodeinput: plain RGBA bytes
Axis and tick detection
src/auto/detect.ts · darkness.ts · skew.ts · lines.ts · frame.ts · ticks.ts
detectAxes finds the X and Y axis lines, the plot box and the tick marks on each axis from the raw pixels, including on slightly rotated scans. Section 3 walks through it.
Tick-label finding
src/auto/labels.ts
findLabels looks in the band beside each axis for the printed tick labels, groups glyphs into words, matches them to ticks and cuts out crops for OCR, remembering where decimal points and minus signs were seen.
Label parsing
src/auto/parseLabel.ts
Turns OCR text into values: signs, thousands separators, 1e-3, 10^3 and superscripts, percentages, years, month names dated from a year label on the same axis.
Scale inference and cross-check
src/auto/suggest.ts · src/auto/auto.ts
suggestAxis fits value against position for each axis, decides linear vs log10 vs date, picks two reference ticks and rates its confidence; crossCheck runs the real engine on the proposal and demands that it reproduce every read label. autoCalibrate strings the whole pipeline together.
Line-tracing engine
src/auto/trace/ (index.ts, color.ts, region.ts, style.ts, curve.ts, kinks.ts, markers.ts, resample.ts, types.ts)
traceLine: from one click on a plotted series, follow its centreline (or find every marker like the clicked one) and propose a set of points. Section 4 walks through it. types.ts is the fixed contract the UI codes against.
Workers and OCRsrc/workers/ · src/ocr/off the main threadoffline
Auto worker
src/workers/auto.worker.ts · src/workers/traceImpl.ts
A module Web Worker that receives the image's RGBA bytes and runs autoCalibrate or (for a trace) detectAxes followed by traceLine, so the page stays responsive. It cannot run Tesseract itself (nested workers are not available everywhere), so each OCR request is posted back to the page and answered with text and confidence.
Tesseract.js pool
src/ocr/pool.ts · src/ui/ocr.ts
A small pool of Tesseract.js OCR workers shared by the app (browser) and the benchmark (Node). Each request carries its own character whitelist (numeric or free text) and page-segmentation mode, with fallbacks when a read comes back empty. The browser side is loaded lazily on first use, so it is not in the initial bundle.
Vendored OCR assets
vite.config.ts (plugin tesseract-assets) → /tesseract/
Tesseract's worker script, WASM cores and English language data are served from the app's own tesseract/ path and copied into the build. No CDN is contacted at runtime, so OCR works offline and the image data stays local; an end-to-end test asserts that no non-local request is made.
State and UIsrc/state/ · src/ui/ · src/components/main thread
Document state and pure reducer
src/state/doc.ts
DocState is the Project plus what it cannot hold yet (refs placed so far, chosen scales, the active line). Every edit is an action handled by a pure reducer, which rejects non-finite pixels; toProject/fromProject convert to and from the saved form.
Undo/redo history
src/state/history.ts
Wraps the reducer with whole-document snapshots. Consecutive edits sharing a group key (one drag, typing into one field, repeated presses of one nudge key) collapse into a single undo step. Loading an image, opening a project, cropping, accepting a suggestion and deleting points are each one step.
View transform
src/ui/view.ts
screen = image · scale + offset. Zoom about the cursor, pan, and Fit change only this transform; stored coordinates are always image pixels, converted once on input.
Canvas drawing and hit testing
src/ui/draw.ts · src/ui/ticks.ts · src/components/Workspace.tsx
Draws the image, refs, points, selection rings, the calibrated axes and gridlines, the ghost suggestions and the crop rectangle. Hit testing is step-scoped: refs are live only in the Axes step, points only in the Data step with the Move tool on.
Loupe, snap, nudge, selection
src/ui/loupe.ts · snap.ts · nudge.ts · selection.ts
The loupe copies source pixels nearest-neighbour at an integer device-pixel magnification so edges stay sharp. Snap finds the coverage-weighted centroid of the marker under the cursor and refuses anything line-sized, so clicks on a curve land where clicked. Nudging moves the whole selection by 1, 10 or 0.1 px.
Autosave and export
src/ui/autosave.ts · src/ui/table.ts · src/ui/export.ts · src/ui/crop.ts
Autosave writes the project to IndexedDB shortly after each change and on page hide. Table rows and CSV/TSV cells come from the same helper with the same options (sort, pixel columns, significant figures, date format), so exports always match what is shown. Crop cuts the decoded image on a canvas and re-encodes it losslessly.
Auto-detect and Auto-trace glue
src/ui/autoDetect.ts · suggestion.ts · autoTrace.ts · trace.ts
Starts the worker, holds the pending suggestion or trace as UI state tagged with the image it belongs to (never in the document, autosave or history), turns it into ghost markers, and on Accept dispatches one undoable action.
React components
src/App.tsx · src/components/*.tsx
App owns the document, history and view; Workspace is the canvas; AxesStep, DataStep, CropPanel, AutoDetectPanel, TracePanel, DataTable, AxesHelp and ThemeToggle are the side panel and toolbar. Components never reimplement maths; they call the engine.

3. Data flow of A Auto-detect axes

Pressing Auto-detect axes sends the image to the worker, which runs autoCalibrate. The goal is a complete suggestion (scale type plus two labelled reference ticks per axis) that the user can accept with one click. The guiding rule is that a wrong suggestion is worse than none: whenever the evidence is inconsistent the pipeline declines (it reports tick positions with blank values, or nothing) rather than guess.

  1. Image RGBA → worker
    src/ui/autoDetect.ts → src/workers/auto.worker.ts
    The decoded image's pixels are copied to the worker. From here on the page only answers OCR requests and shows progress.
  2. detectAxes: darkness map
    src/auto/darkness.ts
    Each pixel's darkness relative to the local mean, so a grey axis on a grey background still counts as ink and filled bars become outlines.
  3. detectAxes: skew estimate
    src/auto/skew.ts · src/auto/frame.ts
    A Hough transform over a few degrees finds the scan's tilt; all later profiles are taken in that rotated frame, so a slightly crooked scan is handled without resampling the image.
  4. detectAxes: axis lines and plot box
    src/auto/lines.ts · src/auto/detect.ts
    For every row and column, the longest gap-bridged run of ink: text never forms one, axes and frame lines do. Runs are continued past small occlusions (a marker drawn on the axis), their position refined to sub-pixel from clean cross-profiles, and the best horizontal × vertical pair that meets like an L, a Γ (an X axis along the top) or a cross becomes the axes. The plot box extends to the far axis ends or to a frame line.
  5. detectAxes: tick lattice
    src/auto/ticks.ts
    Short perpendicular marks on either side of each axis, fitted to an evenly spaced lattice of major ticks; shorter marks between them are minors, and minors at log spacing hint at a log10 axis. An axis without real tick marks gets no invented ticks and zero confidence.
  6. findLabels: bands, glyphs, rows, words, tick matching
    src/auto/labels.ts
    The band outside each axis (below a bottom X axis or above a top one, left of a left Y axis or right of a right one) is thresholded into glyph components (dropping marker-like blobs and colourful data), grouped into text rows and words, and each word is matched to the tick it is centred on (or nearest to, for Y). Without tick marks the label centres themselves stand in for tick positions.
  7. OCR: numeric pass, text pass, layout-restored marks
    src/auto/auto.ts → src/ocr/pool.ts (via the page)
    Each word crop is upscaled and read with a numeric whitelist first; a raised trailing group is read separately as an exponent. A free-text pass runs when the first is unconfident or does not parse. Because OCR drops small marks (it reads "1.0" as "10" with high confidence), decimal points and leading minus signs are located from the glyph layout and re-inserted by position. The axis note matplotlib prints (an offset like +1e4 or a multiplier) is found and read too; an unreadable note makes the axis decline.
    Side channel: the worker posts each crop to the page, the Tesseract.js pool answers with text and confidence, and the worker continues.
  8. parseLabel
    src/auto/parseLabel.ts
    Text → value: sign variants, thousands separators, scientific and 10^k notation, percentages; full dates, years, and month names dated from the year label on the same axis. Bare day numbers are never dated, so such an axis is declined.
  9. suggestAxis: consensus fit
    src/auto/suggest.ts
    Every pair of read labels proposes a value-vs-position line; the line most labels agree with wins and is refined by least squares. Linear, log10 and date interpretations compete on how many labels agree; a log reading also needs a wide enough value span. The two most widely separated agreeing labels with confident OCR become the suggested X1/X2 or Y1/Y2 refs.
  10. crossCheck: the engine must reproduce every label
    src/auto/suggest.ts → src/core/calibrate.ts
    The proposed scales and four refs are given to the real calibrate. It must succeed, and the resulting mapping must predict every agreeing labelled tick in two dimensions within tolerance; otherwise that axis drops to low confidence and no values are suggested for it.
  11. Suggestion with confidence badges
    src/components/AutoDetectPanel.tsx · src/ui/suggestion.ts
    The result is drawn as ghosts (dashed axis lines, a box per read label coloured by agreement, dashed refs labelled with their values) and a panel shows each axis's scale, a High / Medium / Low badge, the reason, and editable values.
  12. User: Accept suggestion
    src/state/doc.ts (action apply-suggestion)
    Only now are the scales and refs applied, as one undo step; Discard drops the suggestion and refs already placed by hand are kept. A partial suggestion (positions without values) feeds the manual flow, which prompts for the missing values.
  13. calibrate
    src/core/calibrate.ts
    The accepted refs go through the same engine as hand-placed ones; the table and overlay update immediately.
The axis benchmark (bench:axes) scores each axis as correct (the right scale and every held-out labelled tick predicted within 1 % of the axis range), wrong (a medium- or high-confidence suggestion that is not correct; the target is none) or declined. Declined axes are left to the user; the known causes are charts without drawn axis lines, low-resolution or JPEG labels that OCR misreads, tiny log exponents, date axes without a year, and unreadable offset notes.

4. Data flow of B Auto-trace

In the Data step a click on a plotted series is sent to the worker as a seed. The worker first runs detectAxes to get the plot box, then traceLine, which returns an ordered path, a list of suggested points with confidences, the series colour and (for curves) its line style. The UI draws the path and the points as ghosts in the line's colour until the user accepts. The request/response shapes in src/auto/trace/types.ts are a fixed contract between engine and UI; traceLine never throws and reports failures (click on background, on the frame, colour too close to the background) with a message.

Curve path

  1. Click on the series
    src/components/Workspace.tsx → src/ui/autoTrace.ts → auto.worker.ts
    The clicked image pixel (pixel-centre convention), the mode (Auto / Curve / Markers) and the point budget are sent with the image.
  2. Region: the plot box
    src/auto/trace/region.ts (+ detectAxes)
    Tracing is confined to the detected plot box when it contains the seed, else to the whole image. An axis or frame line along the box edge is removed only when it has the series' own colour, so a coloured curve lying on a black axis keeps its pixels.
  3. Colour model: background, ink, coverage α, occluders
    src/auto/trace/color.ts
    Each pixel is modelled as background + α·(ink − background) + residual. The background is the region's median colour; the seed is moved onto the nearest, strongest pixel of its own colour; the ink colour is scaled to the typical peak coverage of the stroke, since a thin or antialiased line never shows its full colour. A pixel is "on" when α is high and the residual small (tighter for black and grey, looser for saturated colours that JPEG washes out); ink of another colour is marked as a possible occluder.
  4. Style classification: solid / dashed / dotted / dash-dot
    src/auto/trace/style.ts
    The blobs of ink around the seed are chained along the stroke and their gaps measured. Regular gaps and piece lengths give dashed, dotted or dash-dot; an unbroken stretch gives solid. The style becomes a constraint: same-colour ink of another style is treated as an occluder, which is how two series of one colour, told apart only by their dashes, are kept separate. Gaps in a patterned seed's own line are filled for the walk and undone afterwards.
  5. Column walk: prediction, gap bridging, hidden kinks, retry at forks
    src/auto/trace/curve.ts (traceColumns)
    Column by column from the seed (right, then left primed with the right walk's slope, then right again), the next vertical run of "on" pixels is the one touching the previous or nearest the prediction (previous centre plus recent slope); after a long vertical run (a step), straight through first, else from the run's far end. Gaps over background are bridged up to a modest width, gaps hidden under another colour much further. Under a marker-sized blob of another colour a sharp slope change is allowed (a V under a marker). When a walk dies soon after a fork, the alternatives are walked and the branch that followed the most ink wins.
  6. columnsToPath: centroids, step corners, censor marks dropped
    src/auto/trace/curve.ts (columnsToPath)
    Each column becomes a coverage-weighted sub-pixel centroid. A thin vertical stroke entered at one end and left at the other is a step's riser and yields two corner points; a square same-colour blob sticking out past the curve is a marker and yields one point at its centroid; a thin blob sticking out on both sides (a Kaplan–Meier '+' censoring mark) is dropped and bridged.
  7. Hidden kinks
    src/auto/trace/kinks.ts
    Where the path bridged a compact blob of another colour that the straight stretches on both sides point at, the blob's centroid (or the stretches' intersection) is inserted as a vertex, so a polyline's data points under its markers are recovered; a line ending under a marker is extended to its centre.
  8. resample: ends, corners, extrema, budget
    src/auto/trace/resample.ts
    The suggested points are always both ends, every step corner, every prominent y extremum and every sharp kink, even beyond the budget (a KM curve may get many points rather than lose a corner); the rest of the budget is spread evenly in x over the non-vertical stretches and snapped to traced points.
  9. Review and Accept
    src/components/TracePanel.tsx · src/ui/trace.ts
    The panel names what was found (Curve, Markers or Nothing), the line style when read, the point count and the time; changing the budget or mode re-runs from the same seed. Accept adds the points to the active line (or to a new line coloured like the traced series) as one undo step; Discard changes nothing.
  10. pixelToValue
    src/core/calibrate.ts
    Accepted points are ordinary pixel points; the table shows their values through the calibration like any hand-placed point.

Markers path ("Find points")

In Markers mode, or in Auto mode when the seed's blob is small, roughly round and not part of a dash pattern, the engine looks for markers instead of a line:

  1. Template from the clicked marker
    src/auto/trace/markers.ts (markerTemplate)
    The clicked marker's shape is cut out of its blob even when error bars, caps or lines are attached: for a filled marker, by a morphological opening wider than the attached strokes; for an open marker, from the hole it encloses plus the ring around it. The template records the ink to match, the background that defines the shape (an open marker's inside, a filled one's concave corners) and, for filled shapes, a clear margin that pins the size.
  2. findMarkers: match everywhere in the plot
    src/auto/trace/markers.ts (findMarkers)
    The template is compared at every position; pixels outside the plot or under ink of another colour are treated as unknown. A match needs most of the ink present, most of the defining background clear, and most of the margin clear. Nearby peaks merge into one marker with a sub-pixel centre; a clump of ink several markers large is split by k-means. Without a usable template, a simpler blob match by area and fill ratio is used.
  3. Legend samples excluded
    src/auto/trace/markers.ts (legendSample)
    A found marker with a word beside it (several letter-sized pieces of ink at its height, starting just past its edge) is a legend sample, not data, and is dropped.
  4. Every marker becomes a point
    src/components/TracePanel.tsx
    The point budget does not apply to markers: every match is proposed, and the user accepts or discards as for a curve.
The line benchmark (bench:lines) scores every trace for the kind found, coverage of the series, centreline error against the drawn curve in pixels, wrong-series rate, step corners, markers and line style. Known weak spots are dense staircases in thick lines (lost corners), vertices under small markers in low-resolution JPEGs, a series hidden under another along a step, and markers no thicker than their error bars.

5. The calibration mathematics

Everything in this section lives in src/core/ and is exercised by unit tests on synthetic charts with known geometry (axis-aligned, rotated, sheared, non-square, flipped, transposed) at tight tolerances.

Forward transforms per scale

A scale is a function f from a data value to a coordinate on a straight line, with an inverse f⁻¹. Each has a domain rule; a value outside it yields null, never NaN.

Scalef(v)f⁻¹(u)Domain rule
linearvuany finite value
log10log₁₀ v10ᵘv > 0
lnln veᵘv > 0
reciprocal1 / v1 / uv ≠ 0; the two calibration values must not straddle 0
date/timeepoch milliseconds (UTC)the same, formattedparseable date/time; UTC unless a zone is written

log10 and ln differ only by a constant factor, which the affine fit absorbs, so they give identical output; both are offered for familiarity and a test asserts they agree.

The affine fit: two 3×3 systems

Let the four reference points have pixel positions X1, X2 (known x values x₁, x₂) and Y1, Y2 (known y values y₁, y₂). Write u = fₓ(x) and w = f_y(y) for the transformed values. The engine fits an affine map from image pixels (pₓ, p_y) to the transformed plane:

u = a·pₓ + b·p_y + c      w = d·pₓ + e·p_y + g

Each of the two equations has three unknowns, so three constraints each are needed. The X refs fix u at two points, and the Y refs, which lie on one vertical line of the chart, must share one u. Symmetrically for w:

u(X1) = fₓ(x₁),   u(X2) = fₓ(x₂),   u(Y1) = u(Y2)
w(Y1) = f_y(y₁),   w(Y2) = f_y(y₂),   w(X1) = w(X2)

Subtracting the equation pairs eliminates c and g and leaves two 2×2 systems that share one determinant, the cross product of the vectors X2 − X1 and Y2 − Y1: a solution exists exactly when the X refs and the Y refs lie along non-parallel directions. The value of a point is then (fₓ⁻¹(u), f_y⁻¹(w)). Because the map is affine in both pixel coordinates, it handles rotated, skewed and non-square scans, and the fact that image y grows downward is absorbed automatically. The inverse map (value → pixel) is exposed for drawing the gridline overlay.

Pixel-centre convention

Integer coordinates are pixel centres: pixel column i covers the interval [i − ½, i + ½), so the image's outer edges are at −½ and width − ½. The pixel under the cursor is simply Math.round(px), which the loupe uses, and the hand-labelled fixtures use the same convention (an axis drawn in column 134 is labelled 134). A uniform shift would cancel in the affine fit; the convention matters for display, fixtures and the automatic analysis, which all agree on it.

Error kinds

calibrate returns { ok: false, error } with one of these kinds, checked in this order, each with a user-facing message naming the refs involved. The UI shows the message verbatim under the refs list; nothing downstream ever sees NaN or Infinity.

KindWhen
invalid-pixelA ref's pixel position is not finite.
invalid-valueA typed value is not a plain number, or not a parseable date on a date axis.
out-of-domainThe value is outside the scale's domain (log of 0 or a negative number, reciprocal of 0).
reciprocal-straddles-zeroOn a reciprocal axis the two ref values have opposite signs.
equal-valuesThe two refs of one axis have the same value after the transform (e.g. 2 and "2.0"), so the axis has no extent.
coincident-pointsThe two refs of one axis sit on the same pixel. X1 and Y1 may share a pixel (the usual origin).
singular-systemThe X-ref and Y-ref directions are parallel, so the fit has no unique solution.
numeric-overflowThe values are so extreme that the coefficients are not finite.

After a successful fit, pixelToValue can still return null for a component the scale cannot represent (a reciprocal axis at u = 0, a log value that overflows, a date beyond the representable range); the table shows such cells as "—" and exports them blank.

6. The verification pipeline

A change is not done until npm run verify passes. It runs six steps in order, and the project's rules forbid easing a test, tolerance, fixture, corpus or baseline to make one pass. The same command runs in GitHub Actions on every push and pull request; only when it and the privacy check of the Pages build both pass on main is that checked build deployed.

typecheck
tsc -b · tsconfig.core.json · tsconfig.app.json · tsconfig.node.json · tsconfig.e2e.json
tsc -b over the projects tsconfig.json references. The core project checks src/core and src/auto without the DOM library, so any browser API that creeps into the engine fails the build; the app project checks the UI with the DOM; the node project checks configs and unit tests; the e2e project checks the Playwright specs, scripts and benchmarks.

→

→
CI and deploy
.github/workflows/deploy.yml
GitHub Actions runs the whole gate on every push and pull request, and a separate privacy check (npm run privacy:check) that builds the static site under the Pages subpath, drives a full session on it and fails on any request leaving the app's origin or that subpath. On main, once both pass, the deploy job takes that checked build, smoke-checks that the bundle and the vendored OCR worker are served, and deploys it to GitHub Pages.
