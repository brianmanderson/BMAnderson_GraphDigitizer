# CLAUDE.md

Guidance for Claude Code when working in this repository.

## What this is

A fully client-side graph digitizer: load a chart image, calibrate X/Y axes from two known
points each (linear, log10, ln, reciprocal, date/time), place points, export a table. Vite +
React + TypeScript (strict). Images never leave the browser.

- [docs/SPEC.md](docs/SPEC.md) — the source of truth: workflow, calibration math, data model,
  decisions. If a change alters a decision, update SPEC.md in the same change.
- [docs/prompts.md](docs/prompts.md) — the five build phases, run in order. Phases 1 (engine),
  2 (digitizing UI + e2e) and 3 (loupe, nudging, snap, undo, autosave, project files) are done.

## Layout

- `src/core/` — pure-TS calibration engine, **no DOM**: `scales.ts` (transforms + domains),
  `dates.ts` (UTC parse/format), `calibrate.ts` (affine fit, typed errors), `project.ts` (data
  model), `projectFile.ts` (validate + migrate saved JSON). Tests sit beside the code.
- `src/state/` — `doc.ts` (`DocState` + pure reducer), `history.ts` (undo/redo); `src/ui/` —
  helpers (view, drawing, loupe, snap, nudge, table/CSV, IndexedDB autosave); `src/components/`.
- `e2e/` — Playwright specs; `fixtures/real/` (hand-labelled) and `fixtures/synthetic/`
  (generated by `scripts/make-synthetic-charts.ts`) with ground-truth JSON beside each image.
- `tsconfig.core.json` checks `src/core` without the DOM lib; `.app` the UI; `.node` configs and
  core tests; `.e2e` Playwright specs and scripts.

## Commands (npm only — not pnpm/yarn)

- `npm install` once; `npm run dev` serves http://localhost:5173 (launch.json `dev` for the pane).
- `npm run build` — type-check + production bundle in `dist/`.
- **Verification gate** — a change is done only when this passes (`npm run verify` runs it):
  `npm run typecheck && npm run lint && npm test && npm run test:e2e`. Never ease a test,
  tolerance or fixture to make it pass. From Phase 4 on, `npm run bench:axes` must not regress.
- `test:e2e` needs `npx playwright install chromium` once and runs its own server on :5174.

## The skills are the operational manual

Tracked in `.claude/skills/`; their descriptions say when to load them:

- `calibration-engine` — BEFORE changing anything in `src/core/` or code that calls it: the
  invariants (pixels stored, values derived; typed errors, never NaN/Infinity; UTC dates) and
  which tests prove them.
- `verify` — running the gate (unit + e2e), reading failures, and the test-environment quirks
  (the unit suite runs in `America/New_York` on purpose).
- `digitizer-ui` — BEFORE changing `src/state`, `src/ui`, `src/components` or `e2e/`: state,
  undo grouping, view transform, step-scoped interaction, loupe/snap/autosave rules.

## Pitfalls

- When searching, exclude `node_modules/`, `dist/` and `.claude/worktrees/`.
- `src/core` must stay DOM-free (workers in Phase 4–5 import it). `tsc` rejects DOM globals
  there and ESLint flags `window`/`document`; don't "fix" that by adding the DOM lib.
- Dates are UTC unless the text carries a zone. Never use `new Date(string)` or local-time
  getters in `src/core` — they depend on the host zone and DST.
- By design: `log10` and `ln` give identical output; ambiguous dates (`03/04/2024`) are rejected.
- A Project schema change bumps `PROJECT_VERSION` and adds a migration (`src/core/projectFile.ts`).
- Integer pixel coordinates are pixel *centres* (SPEC → Pixel convention); keep it in fixtures.
- Windows: stop a running `npm run dev` before deleting `node_modules` or `dist`.
- Reloading the app restores its IndexedDB autosave; clear site data for a clean start.
