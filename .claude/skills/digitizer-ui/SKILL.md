# Digitizing UI

## Rules

1. **All document edits go through App's `dispatch(action, group?)`**, which feeds
   `historyReducer` (`src/state/history.ts`) → `appReducer` → `docReducer` (`src/state/doc.ts`).
   Never call `docReducer` from components or bypass the history: undo would miss the edit. Ids
   are generated by the caller (`crypto.randomUUID()` in App) so reducers stay pure. The reducer
   rejects non-finite pixels. Non-document UI state (step, selection, view, table view options,
   hovered marker, loupe/snap/move-tool prefs) lives in `App.tsx` / `Workspace.tsx`, not in
   `DocState`. The selection is a `Selection` (`src/ui/selection.ts`): one ref, or many points in
   pick order (last = current). It is validated against the document each render
   (`validSelection`: an undo or a deleted line may remove its points). Multi-point edits are one
   action each — `delete-points`, `move-points` — never a loop of single-point actions.
2. **Stored coordinates are image pixels, integer = pixel centre.** Convert input once with
   `screenToImage(view, …)`; never store screen or view values. The image is drawn at
   `offset − scale/2` so pixel `i` covers `[i − ½, i + ½)`.
3. **Values only via the engine**: `calibrateSpec(calibrationSpec(doc))`, then
   `pixelToValue` / `pixelToLinear` / `linearToPixel` / `forward`. `src/ui/ticks.ts` only picks
   round values; positions always come from the calibration.
4. **View updates are functional** (`onViewChange(v => panBy(v, dx, dy))`): several pointer or
   wheel events can arrive before React re-renders, and a non-functional update drops deltas.
5. **Markers are step-scoped** (`hitTest(…, step)`): refs in Axes, points in Data. In Axes a
   click without movement on another ref places the pending ref (X1/Y1 share the origin); only
   a drag past `CLICK_SLOP` (3 px) moves a marker. `e2e/real-km.spec.ts` guards this.
   In Data, points are live only with the **Move points** tool on (`prefs.movePoints`, `M`):
   off ("place" mode, the default) Workspace never hit-tests or hovers points — every click
   places on the active line, drags move nothing. Don't reintroduce a grab in place mode: placing
   beside another line's point must stay safe (`e2e/edit-modes.spec.ts`).
6. **Exports = the table view**: `exportCells` takes the same `TableOptions` the table renders
   with; `null` values export as blank cells. JSON export is `toProject(doc)`.

## Undo grouping

Consecutive edits with the same `group` key merge into one undo step; anything else starts a
new one. Keys in use: `drag:<gesture id>` (Workspace numbers each pointerdown → pointerup),
`value:<ref>`, `rename:<id>`, `recolor:<id>`, `settings:<key>`, and
`nudge:<selection keys>:<key>:<amount>` (repeats of one arrow+modifier on one selection). A drag
of a multi-selection is one `move-points` per pointer move under `drag:<gesture id>`. `set-active-dataset` is never a
step (`UNRECORDED`). A new continuous edit needs a group key, or a drag becomes dozens of steps.
`history.rev` changes on every recorded change; a notice's Undo button is shown only while
`notice.undoRev === history.rev` (it must undo *that* action, not whatever came later).

## Precision tools and persistence (Phase 3)

- **Loupe**: drawn by `drawLoupe` from the decoded `HTMLImageElement` (never the main canvas),
  integer device px per image px (`loupeCell`), origin rounded (`loupeOrigin`). The element has
  `pointer-events: none`; keep it, or e2e clicks under it hit the loupe. Its centre is the drag
  target, else the just-nudged selection (`loupeOnSelection`, cleared by any pointer move), else
  the cursor while placing or hovering a marker.
- **Nudge**: App's keydown handler; same step scoping as drags; `nudged()` clamps and rounds.
- **Snap**: `findSnapTarget` is pure and unit-tested on synthetic RGBA; Workspace reads pixels
  once per image (`imagePixels`). Only new Data-step points snap. If you change the algorithm,
  run `src/ui/snap.test.ts` and the snap e2e (the KM plateau must stay unsnapped).
- **Persistence**: `toProject`/`fromProject` for both autosave and files; anything read back goes
  through `parseProject` (src/core). Restoring an autosave dispatches `{ type: 'reset' }` (no
  undo step); opening a file or loading an image is `replace-doc` (an undo step). App's image
  effect re-decodes and re-fits whenever `doc.image` changes identity, which covers undo across
  a load.

## Auto-detect (Phase 5)

- App keeps `AutoState` (`src/ui/suggestion.ts`) tagged with the image it was made for — UI state,
  not in `DocState`, autosave or history. `runAutoDetect` (`src/ui/autoDetect.ts`) starts the
  worker; the Tesseract pool is created on first use and kept.
- Ghost markers: `drawWorkspace({ …, ghost })` draws `ghostOf(auto)` in the Axes step only; they
  are not hit-testable. Editing a suggested value changes only `AutoState`.
- Accepting = `dispatch(acceptAction(result, values))` → `apply-suggestion` (one undo step,
  replaces the suggested refs and sets the detected scales, keeps other refs). Never dispatch it
  without the user pressing "Accept suggestion".

## Auto-trace

- `TraceState` (`src/ui/trace.ts`) lives in App, tagged with its image and shown in the Data step
  only; `traceSettings` (mode, `maxPoints`) persist for the session. Each trace carries its own
  `mode`: "Auto-trace line" starts in the session mode, "Find points" in 'markers' without
  changing the setting (prompt `promptFor(mode)`: `FIND_PROMPT` vs `TRACE_PROMPT`). App's trace effect starts a
  run (`runTrace`, `src/ui/autoTrace.ts`) whenever the state is `running` — a new seed object or
  new settings — and cancels it on cleanup; never trace on the main thread.
- The worker reaches the tracer only through `src/workers/traceImpl.ts` (the single seam to
  `src/auto/trace/index.ts`). `src/auto/trace/types.ts` is a contract shared with the
  engine: change it only together with the engine.
- While a trace is open Workspace gets `tracing`: clicks call `onTraceSeed`, `hitTest` is
  skipped, snap is off. The ghost is `traceGhostOf(doc, trace)` → `drawWorkspace({ …, trace })`.
- Accepting = `dispatch(acceptTraceAction(…))` → `add-points` or `add-dataset` (one undo step).
  Never without the user pressing "Accept".
- It is the Data step's **default tool**: App's `defaultTrace(doc, mode)` opens it (picking, into
  the active line) from `goStep('data')`, `replaceDoc`, the autosave restore and `addDataset`,
  only when the document is calibrated; DataStep's prompt then says so. Discard/Esc close it and
  nothing reopens it until the step is entered or a line added again. Specs that place points by
  hand call `placeByHand(page)` (e2e/helpers.ts) after entering Data or adding a line;
  `e2e/auto-trace.spec.ts` guards the default.

## Crop (toolbar and Image step)

- Crop mode is App state `{ of: doc.image, rect }` tagged with the image like `AutoState` (never
  in `DocState`, the autosave or the prefs); `goStep`, `replaceDoc`, Esc and Cancel clear it.
  Both "Crop…" buttons (toolbar `File` group, beside Open image…; the Image step) call
  `toggleCrop`, which enters crop mode on the Image step (`goStep('image')` first when elsewhere,
  then `setCrop`) or leaves it when already in it. Keep the toolbar one: loading an image moves
  straight to Axes, so the Image step's button alone is never seen.
  Workspace gets `crop={ rect, onRect }` and turns a left-drag into `onRect(cropFromDrag(…))`
  (`src/ui/crop.ts`: every pixel the drag touched, whole px, clamped, ≥ 2 × 2); the panel's
  fields (`CropPanel.tsx`) go through `setCropField`, starting from `fullCrop` until a rectangle
  exists. The canvas draws it via `drawWorkspace({ …, crop })` (dim outside, dashed outline).
- Apply = `cropImage(image, doc.image, rect)` (canvas → PNG data URL, same name) then
  `dispatch({ type: 'crop', image, x0, y0 })`: one undo step, no group key. The reducer translates
  refs and points by (−x0, −y0) and drops those outside the new image (closed box, like
  `isOnImage`); `cropLosses` counts them for the notice. The `docImage` effect re-decodes and
  re-fits on its own. Never keep the original image in the Project (no schema change).

## Session log

- `SessionRecorder` (`src/ui/sessionLog.ts`, pure, clock injected) lives in App (`useState`),
  never in `DocState`, history, autosave or prefs. App's `dispatch(action, group?, opts?)` logs
  `eventsForAction(doc, action, group)` before the history applies it (skipped when the reducer
  would ignore the edit); events with the same group key merge like undo steps, so a new
  continuous edit's group key also keeps it to one log event. Outcomes the reducer cannot see
  are recorded at their call sites: Auto-detect (`autoDetectEvent`), trace runs (the trace
  effect, not inside a `setState` updater — StrictMode calls those twice), Accept/Discard of
  suggestions and traces (`noteTraceDropped`), undo/redo, snap and trace settings, exports.
- `replaceDoc(next, text, source)` and the autosave restore call `startLog` (a new log per
  image); results that arrive after a newer load are dropped by `sessionLog.generation`.
- Never put image data in an event; `serializeLog` strips it anyway. SPEC → Session log lists
  every event; add a new one there and in `e2e/session-log.spec.ts`.

## Side panel and table

- `.panel` is a flex column: step tabs · `.step-scroll` (the step's controls, `flex: 0 1 auto`) ·
  `.table-panel` (`flex: 1 1 0`, `min-height` 136 px). The step never shrinks while the table is
  above its minimum; don't give the step area a `max-height` or the table a content-sized basis,
  or long lines squeeze the controls again. `e2e/data-panel.spec.ts` checks the button boxes.
- Collapsed lines (`collapsed: ReadonlySet<string>` in App) are UI state: autosaved beside
  `activeDatasetId`, never in `DocState`/Project, never filtering exports. A collapsed line's
  table is not rendered (`tableRows` returns `[]`). `onSelect`/`onAddPoint` call `expandLine`;
  DataTable scrolls the selected row (`tr[data-point-id]`) into view on a new selection.
- Hidden lines (`hidden: ReadonlySet<string>` in App, the eye in each DataStep row) are UI state
  autosaved the same way, never in `DocState`/Project/history, never filtering the table or
  exports. Workspace gets `hiddenLines` and passes it to `drawWorkspace({ hidden })`, `hitTest`,
  `pointsInRect` and the loupe markers; App's `selection` is `withoutHidden(validSelection(…))`,
  so nothing reaches a point the user cannot see. A line that becomes active is shown by a
  render-time adjustment on `activeDatasetId` (lint forbids setState in an effect);
  `onAddPoint`, `onSelect`, `onSelectLine` and trace Accept call `showLine`. A new path that
  picks or adds points must not bypass these. `e2e/line-visibility.spec.ts` guards it.

## Notices

- The notice (`data-testid="notice"`, its Undo and ✕) is a snackbar in `.notice-layer`, a child
  of `.main` over the bottom of the workspace column (SPEC → Notices). Don't put it back in the
  toolbar or give it toolbar width: on the Linux CI font the toolbar has no room left at 1366 px,
  and a wider slot wraps the toolbar and squeezes the table. Keep the layer and text
  `pointer-events: none` (only buttons catch clicks). `e2e/notice.spec.ts` runs with a wide font.

## e2e hooks — keep them

- Canvas `data-testid="canvas"` with `data-scale`, `data-offset-x`, `data-offset-y` (the view).
- Loupe `data-testid="loupe"` with `data-corner`, `data-px`/`data-py` (exact centre),
  `data-cell`, `data-origin-x`/`-y` (device-pixel mapping), `data-snap-px`/`-py` when a snap
  target is shown; caption `loupe-pixel`. `e2e/helpers.ts` → `loupeState()`.
- `project-input` (Open project), `autosave` (status bar); IndexedDB via `readAutosave()`;
  `session-log` (toolbar "Session log", accessible name "Download session log").
- Toolbar groups `History` (Undo/Redo; a notice may have its own "Undo" button, so scope to the
  group), `Precision` (`Loupe`, `Snap` toggles with `aria-pressed`, `Loupe zoom` select) and
  `Edit` (`Move points` toggle, `aria-pressed`, disabled outside Data). Shortcuts (`M`, `Z`, `S`)
  are ignored while a form control has focus — specs click the button or blur first.
- Crop: `image-current` (the "Current: name, W × H px" line), `crop-panel`, `crop-left`, `crop-top`,
  `crop-width`, `crop-height`, `crop-size`, `crop-apply`, `crop-cancel`; both "Crop…" buttons
  carry `aria-pressed` — scope a locator to the toolbar group `File` or the Image step region
  (`section[aria-label="Image"]`), or it matches two. `e2e/crop.spec.ts` drives the crop through
  the fields, with a mouse drag, and from the toolbar on the Axes and Data steps.
- `data-testid`: `workspace`, `file-input`, `notice`, `axes-prompt`, `calibration-ok`,
  `calibration-error`, `calibration-pending`, `date-hint`, `zoom-level`, `table-<line name>`,
  `auto-suggestion`, `auto-running`, `auto-error`, `auto-x`/`auto-y`, `auto-badge-x`/`-y`,
  `auto-message-x`/`-y`, `auto-timing`, `data-prompt`, `trace-prompt`, `trace-panel`, `trace-running`,
  `trace-error`, `trace-kind`, `trace-style` (curves whose line style was read), `trace-count`.
- Selected table rows carry `aria-selected="true"`; buttons `Delete N points` / `Delete selected
  points`, `Select all points of <name>` (line header).
- Accessible names used by specs: `X1 value`…`Y2 value`, `X scale`, `Y scale`, `Pixel columns`,
  `Sort by X`, `Significant figures`, `Collapse all`, `Expand all`, line headers `Line 1 (n)`, `Date format`, `Line name`, `Lines`, `+ Add line`, `Make <name> active`, `Auto-detect axes`,
  `Suggested X1 value`…, `Accept suggestion`, `Discard`,
  `Delete <name>`, `Hide <name>` / `Show <name>` (the eye), `Auto-trace line`, `Trace into a new line`, `Points`, `Number of points`,
  `Trace mode`, `Find points`, `Find points into a new line`, `Accept`, `Colour of <name>`, the `Steps` navigation and the export button labels.

## Fixtures

`npm run fixtures:synthetic` regenerates `fixtures/synthetic/*` from
`scripts/make-synthetic-charts.ts` (draws at canvas `v + 0.5` so JSON pixels are centres).
Never hand-edit the JSON; change the generator and commit PNG + JSON together.
